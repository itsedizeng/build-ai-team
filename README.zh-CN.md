# Build AI Team

[English](README.md) | [简体中文](README.zh-CN.md)

> 正式版：`v1.0.1`

**先判断一个 Agent 是否足够；确需协作时，只规划最小可靠的持久 AI 团队，并给出清晰所有权、角色级模型配置和来源可核查的 Skill 推荐。**

针对多种真实项目场景优化，覆盖软件、产品、设计、研究、数据、内容、系统迁移和发布等工作。

给 Build AI Team 一个真实需求。它会从最终结果倒推：一个 Agent 够用就不拆；只有职责所有权、隔离或协作价值明确时，才增加持久角色。

```text
你的需求 → 一个 Agent 或最小可靠团队
→ 角色所有权与模型配置 → 由你确认
```

## 核心能力

- **团队够用就好。** 先判断一个 Agent 是否足够；只有职责所有权、隔离或协作价值明确时，才增加持久角色。
- **每个角色都有明确结果。** 当前角色都要写清唯一责任、负责结果、依赖和边界。
- **按责任推荐模型。** 给出默认模型和推理强度，并说明升级条件；安全可行时再给节省 Token 的模型配置。
- **区分本地 Skill 与公开候选。** 用户要求公开搜索时，再核对适用性、来源、维护信号和权限风险，不把推荐说成已安装或安全认证。
- **继续利用当前规划对话。** 用户确认后，当前对话可在适用时继续担任有实质工作的主控，只创建其余必要的持久任务。真实持久任务就是团队状态，不生成 `AI_TEAM.md` 成员清单。
- **新项目默认独立判断。** 相同文件夹、相似标题、旧任务、记忆或旧团队方案不能单独证明是同一项目；只有用户明确继续同一项工作时，才复用既有范围与任务。
- **把重要动作分开。** 规划、建队、公开搜索 Skill、安装、登录、私有数据访问、写入、上传、发布和删除不是同一次授权。

> 规划 ≠ 建队 ≠ 搜索 Skill ≠ 安装 ≠ 外部权限。

## 快速开始

仅显式调用：选择 Build AI Team 或输入 `$build-ai-team`；普通需求和提及不会自动触发。

安装后新建 Codex 任务，直接输入一个真实需求：

```text
$build-ai-team 我想做一个能上架 App Store 的记账 App，请给我团队建议。
```

第一次响应只给方案。没有针对具体动作的确认，不会建队、安装 Skill、连接账号、读取私有数据或写入外部系统。

## 它不会自动做什么

- 创建 Agent 或长期任务；
- 安装或运行第三方 Skill；
- 连接账号或业务系统；
- 读取私有数据；
- 写入、上传、发布或删除内容；
- 保证第三方 Skill 安全、最新或一定适用；
- 保证所有行业只有唯一正确的团队人数。

## 在 Codex 项目中安装

1. 下载或克隆本仓库。
2. 将完整的 [`build-ai-team/`](build-ai-team/) 文件夹复制到目标项目的 `.agents/skills/` 目录。
3. 最终路径应为：

```text
<project>/.agents/skills/build-ai-team/SKILL.md
```

4. 同一版本的五份运行文件必须保持完整：

```text
build-ai-team/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── curated-skills.md
    ├── model-routing.md
    └── skill-discovery.md
```

5. 新建一个 Codex 任务，显式选择 Build AI Team，或输入：

```text
$build-ai-team 我想做一个能上架 App Store 的记账 App，请给我团队建议。
```

不要只复制 `SKILL.md`，也不要把整个仓库根目录放进 `.agents/skills/`。更新时请整体替换五份运行文件，不要混用不同版本。

如果 Skill 没有出现，先检查目录层级、`build-ai-team` 文件夹名称和五份文件是否完整，再考虑其他处理方式。

## 更新或卸载

- **更新：** 用同一个新版本的完整 `build-ai-team/` 文件夹替换原来的五份运行文件，核对 `SHA256SUMS.txt`，然后新建 Codex 任务。不要混用不同版本的文件。
- **卸载：** 只删除 `<project>/.agents/skills/build-ai-team/`，然后新建 Codex 任务。不要删除上层 `.agents/skills/` 目录，因为其中可能还有其他 Skill。

卸载后，后续新任务不再加载本 Skill；它不会撤销用户此前另行确认创建的团队、文件、安装、账号访问或外部动作。

## 如何理解团队方案

- `Required／必要`：方案确认后属于当前团队。
- `Required if…／具体条件成立时必要`：只有可观察条件成立后才出现该工作包，当前不创建。
- `Optional／建议`：可以提高质量、速度或覆盖度，但不是完成当前目标所必需，默认不创建。
- `Owner`：某个工作包或交付物的唯一负责人。
- `project lead／主控`：由一个已有实质角色兼任，额外负责计划、依赖和最终交接状态；不会自动取得其他专业交付的所有权。
- 独立验证者：不参与被审对象的生产，也不修改被审结果。

## 本地适用 Skill 与公开搜索

首次方案会把宿主直接提供的本地适用 Skill 与小型离线索引中的未核验公开线索分开显示。只有用户明确要求时，才开始公开来源的实时只读搜索；搜索不会重复本地列表，并会继续保留原方案的主要下一步。

推荐不等于安装；安装也不等于允许运行脚本、登录、读取私有数据、写入、上传、发布或删除。使用第三方 Skill 前仍应核对文件、权限和许可。

第三方项目名称和链接仅作为参考，不代表认可、合作关系、当前兼容或安全认证；这些项目仍适用各自的许可。
